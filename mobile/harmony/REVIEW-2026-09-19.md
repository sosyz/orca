## 功能与数据对齐结论

Harmony 的 `metro.config.js` 复用 `mobile/app`、`mobile/src` 与共享协议；没有第二套宿主、工作区或配对数据模型。适配边界主要是导航、Expo 原生 API 与 ArkTS 资源。

| 领域           | 源码结论                                                                              | 仍需设备／集成验收                       |
| -------------- | ------------------------------------------------------------------------------------- | ---------------------------------------- |
| 配对与凭据     | 共用 pairing、host-store、E2EE；Harmony 使用 HUKS 加密存储，失败不会退回 web 明文存储 | 真机扫码、锁屏、升级及 HUKS 异常生命周期 |
| Direct／Relay  | 共用逻辑客户端、重连和订阅重绑；本轮补齐 Relay 取消语义                               | 蜂窝／Wi-Fi 切换、后台恢复、旧宿主联调   |
| 页面与导航     | Harmony 注册共享任务、会话、文件、历史、源码管理、review、账户和设置页面              | 页面注册覆盖不等于全部交互验收           |
| 会话与文档     | 共用终端、聊天与文档状态；本轮修复保存范围隔离和中断读取恢复                          | 真机切页、远端并发编辑和输入法组合       |
| SSH            | 执行仍由宿主 RPC 所属执行端负责；断线没有被改成进程退出                               | 真实 SSH 失联及重连全链路                |
| 普通目录工作区 | 共享类型和列表规则保留 `folder-workspace`，没有新增 Git 必需假设                      | 真机创建、打开和关闭目录工作区           |

导航保留策略仍有平台差异：Harmony 只挂载活动路由，部分会话状态由内存 owner 保留；这不等于 Expo 原生栈保留整棵页面，也不提供进程结束后的草稿持久化保证。第一轮未引入新的 wire 字段、opcode 或凭据格式；后续新增的兼容 RPC／可选元数据在相应检查点单独说明。

## 已修复问题

1. **Relay 会话／聊天订阅未释放。** 宿主的 snapshot 不一定包含 `subscriptionId`，原取消逻辑因此遗漏 `session.tabs.unsubscribe`／`nativeChat.unsubscribe`。复用直连的 `buildStreamUnsubscribe`；连接前已取消的排队请求只清理本地，避免误取消同键订阅。9 个新增测试覆盖 snapshot 前后、显式／旧版 token、重复取消与晚到消息。文件：`mobile/src/transport/mobile-relay-rpc-streams.ts`。
2. **安全存储重建后可能读取未落盘值。** 同一进程的新 `SecureValueStore` 实例原先绕过旧实例的写入队列和失败状态。现在相同存储命名空间共用队列和持久化不确定状态；成功 flush 后恢复读取。新增跨实例失败、恢复和排队测试。文件：`entry/src/main/ets/native/SecureValueStore.ets`。
3. **录音取消后的迟到错误干扰后续会话。** 已取消／超时启动的释放失败不再发送过期 `blocked` 事件。原生音频行为测试覆盖该异步顺序；实际 OS 释放失败的资源结果仍需设备验证。文件：`entry/src/main/ets/native/HarmonyAudioService.ets`。
4. **缓存写失败的清理顺序不完整。** 写入失败先尝试关闭句柄，再删除残片；关闭失败也进入清理，保留原写入错误。文件：`entry/src/main/ets/native/HarmonyFileService.ets`。
5. **编码后的主机首页被误判为详情页。** 共用导航函数同时识别 Expo 解码路径和 Harmony 编码路径，覆盖包含 `/`、`#`、`%` 等字符的 ID。文件：`mobile/src/navigation/host-stack-navigation.ts`、`mobile/app/h/_layout.tsx`。
6. **原生 picker 缺失被伪装为用户取消。** 图片／文件适配器现在明确报告不可用，仍保留真实取消与原生异常的语义。文件：`src/compat/expo-image-picker.ts`、`src/compat/expo-document-picker.ts`。
7. **保存响应越过工作区／标签生命周期。** 文档保存使用范围与请求身份隔离，关闭或换页后的旧响应不再写回；保留编辑器迟到的新输入，基于已确认版本继续保存。保存成功／失败状态提交前不会接受下一次保存，避免 React 批处理下丢失更新。文件：`mobile/src/session/mobile-markdown-save.ts` 及共享 Session route。
8. **断线中断文档读取后永久加载。** 清理中断的 loading／refreshing 状态并隔离旧读取，重连后恢复活动文档读取，保留脏草稿，不按失败结果自动循环重试。文件：`mobile/src/session/mobile-session-document-refresh.ts` 及共享 Session route。
9. **宿主在取消后重新注册会话订阅。** 已复现恢复结构化标签或读取首次列表期间取消，随后仍新增监听器。宿主现在在异步初始化阶段记录取消与连接中止，再交接给既有 cleanup 机制；按连接、请求和解析后的工作区隔离，并只取消取消请求开始时已存在的待初始化订阅。14 项生命周期测试覆盖两处等待、别名、隔离及旧取消／新初始化顺序。文件：`src/main/runtime/rpc/methods/session-tabs.ts`。

## 继续优化：额度价值优先

用户要求持续优化并明确禁止使用重置卡。继续复用上述团队；仅在相关代码发生变化或出现新风险时扩大验证，不以重复运行消耗额度。配额只读检查；未调用重置。

本阶段已实现：

- **旧取消误清新活动订阅**：宿主在异步解析工作区前同时捕获已有 cleanup owner 与 pending setup。pending 转 active 后保留注册 handle，只释放被捕获的 owner；同一个 requestId 重用也不会误清 replacement。4 个宿主定向文件 52 项、runtime capture 3 项通过，含真实加密 socket 集成。
- **通知先后顺序与原子清理**：先监听再读取初始通知；新点击使旧异步导航失效，卸载后停止导航。Harmony 原生增加按 ID 比较清除能力；新 shell 不会清掉刚到的新响应，旧 shell 和 iOS/Android 保留兼容路径。5 个定向文件 46 项通过，codegen 和两套 TypeScript 通过。
- **首帧永久等待**：首帧 deadline 直到 native Image 解码提交才结束；ready 或收到二进制并不代表画面可用。解码失败/不回调会在 15 秒超时，清理积压后仍可接受后续有效帧。卸载时隔离晚到 stream 回调。
- **投屏结束后恢复**：宿主主动 end 后停止加载并禁用旧画面的输入；Reload 会重新订阅。被过滤的 selector 错误不再取消首帧 deadline。浏览器当前 52 项测试通过。
- **投屏队列减少编码**：等待 native decode 时仅保存最新原始帧，真正开始 decode 才转 Base64。确定性测试中，首帧等待期间积压 100 帧，编码总数从 101 次降至 2 次；这不是设备耗电或 FPS 基准。
- **终端桥接与测量**：忽略 null/primitive/array 消息；测量回复携带桥接请求 ID，旧测量不能完成新请求；HTML rAF 重试保留 ID。拒绝非整数/非安全整数尺寸；桥接发送失败会清 timer/ref 并返回 null。57 个终端测试文件 571 项通过。
- **断线重放旧订阅 ID**：重放前清理上一个 socket 分配的 subscriptionId；新流 ready 前取消时不再向旧 token 发送无效 unsubscribe。6 个传输定向文件 53 项通过，覆盖真实连接的两轮重连和旧 socket 晚到 ready。
- **网络恢复 seed 竞态**：首次 online 事件早于异步网络快照时仍触发恢复；重复状态不会反复 nudge，卸载后的排队回调忽略。4 个相关文件 32 项通过。
- **选中文件清理**：拷贝完成后源文件 close 失败也清理缓存；同时发生拷贝和关闭错误时保留原拷贝错误。复用已验证的 stat 大小，安全处理缓存名中的 ?/#，区分 HEIF MIME。
- **原生 lint 误报成功**：wrapper 对 DevEco 内部错误、非 JSON/畸形记录、缺源文件报告和错误级缺陷返回非零。7 项 parser 回归已加入 release-scripts。实际根因是本机 arm64 无法运行 DevEco 内置 x86_64-only performanceAgent/hpaudit；未改 SDK 或关闭规则。现 lint 明确失败，源码密钥扫描单独通过。
