# Harmony review and simulator validation — 2026-09-06

Historical review snapshot, not whole-client acceptance. Later findings, fixes,
current validation and the unresolved preserved-device credential incident are
tracked in [ACCEPTANCE-PLAN.md](./ACCEPTANCE-PLAN.md). The counts and artifacts
below predate that work and must not be presented as the final delivery.

Three GPT-5.5 xhigh reviewers covered navigation/compatibility, terminal/file
rendering, and native services/release boundaries. A Luna reviewer independently
ran the final regression suite. The coordinating reviewer checked the changes
and exercised the installed application through HDC UI automation.

## Accepted changes

- Preserve repeated route query parameters as arrays, safely treat prototype
  names as ordinary own parameters, reject inherited dynamic route parameters,
  avoid empty host navigation stacks, and skip equal-array parameter updates.
- Release stale file/diff highlighting state when the reader changes document
  kind or leaves ready state. Memoize plain source fallback segments.
- Keep the HTML preview document and WebView source object stable across renders
  when HTML has not changed.
- Attempt every image resource cleanup even when an earlier release fails;
  synchronous throws and promise rejections cannot replace the operation result.
- Recheck the copied picker file size before exposing it to JavaScript; discard
  an oversized copy. Require canonical, bounded notification cancellation IDs.
- Align connection-log credential redaction across camelCase, underscore and
  hyphenated keys, including encoded query keys and pairing fragments after a
  query string. Regression inputs use synthetic credentials only.

The proposed source-text virtualization was withdrawn during integration review:
fixed row measurements were incompatible with wrapped lines and headers, and
cross-line selection would regress. Existing text selection, zoom, highlighting
budgets, virtualized diff rows, terminal batching, and platform mount policies
remain intact. No new protocol or SDK floor was introduced.

## Simulator evidence

Environment: Huawei_WideFold, HarmonyOS 6.0.1/API 21, arm64, portrait
1320 × 2120. Installed with replacement, without uninstalling or clearing data.
The existing local mock server supplied synthetic worktrees, files and terminal
output over an HDC reverse mapping. It does not execute real terminal commands.

Verified interactions:

- Pairing confirmation, encrypted handshake, connected host and worktree list.
- Terminal initial rendering, character input reaching the mock server, and
  Enter producing a carriage return. Returning to the worktree list sent a
  terminal unsubscribe request.
- Files → source preview; 100% → 120% increased actual text bounds from 114 to
  136 physical pixels high. The final installed build repeated this check.
- Returning to the terminal and background/foreground recovery.
- Terminal settings and shortcut up/down reordering; the original order and
  source zoom were restored afterward.
- Final HAP replacement, cold start, persisted pairing, reconnect, terminal
  rendering and file preview. The captured final application log had no matches
  for fatal, uncaught, TypeError, ReferenceError or app-crash markers.

After the interaction run, the log-redaction-only follow-up was separately
regression-tested, rebuilt and installed with a fresh cold-start smoke check.

Local screenshots/layouts/logs: `/private/tmp/orca-review-e2e.mYrlgB`.
The final screenshots are `final-terminal.png` and `final-code-zoom.png`.
Stair-step lines in the mock terminal output come from its LF-only streaming
fixtures; they are not evidence of incorrect client cursor handling. Production
terminal bytes were not rewritten to hide that fixture behavior.

The temporary Host 4 pairing and reverse mapping were removed, and the mock
server was stopped. Original Host 1–3 pairings were preserved. The emulator and
final installed app remain available.

## Limits and follow-up

- Horizontal/fold-state E2E is unverified: the installed Emulator 6.0.1.200
  rejects the newer documented `-instance`/rotation control interface.
- This is simulator/mock evidence, not physical-device FPS, sustained memory,
  real desktop/relay, notification delivery, camera, clipboard-image or audio
  end-to-end acceptance. An isolated process RSS reading is not a performance
  comparison and is not used to claim a memory improvement.
- Large-source virtualization remains deferred until wrapping, positioning,
  selection and device scroll behavior can be validated together.
- External dependency auditing was not rerun without authorization to disclose
  the dependency graph. This review does not certify dependency vulnerabilities.
- Changes remain local; no commit or push was performed.
